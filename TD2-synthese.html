Les 4 éléments d'un skill/gem efficace

1

Clarté du déclencheur

Les mots-clés de votre description (Claude) ou le nom du Gem (Gemini) doivent être explicites et couvrir les variantes.

2

Workflow structuré

Les étapes doivent être numérotées, impératives, et progresser logiquement du contexte à la sortie finale.

3

Contraintes explicites

Listez ce que l'IA DOIT faire et ce qu'elle NE DOIT PAS faire. Les règles critiques en majuscules.

4

Sortie standardisée

La structure de sortie (format, sections, mise en forme) doit être parfaitement définie. Pas d'improvisation.

Bilan comparatif : Claude vs Gemini

Claude + Skills

✅ Forces
  • Exécution de code (Python, Node.js) directement
  • Génération de fichiers .docx, .xlsx, .pptx natifs
  • Déclenchement automatique = moins de clics pour l'utilisateur
  • Versionning facile (Git)
❌ Faiblesses
  • Configuration par session (relit le fichier à chaque fois)
  • Complexité : YAML frontmatter + Markdown + code
  • Moins bon pour les longs documents (< 200k tokens)

Gemini + Gems

✅ Forces
  • Intégration native Google Workspace (Slides, Docs, Sheets)
  • Contexte long (jusqu'à 2M tokens)
  • Fichiers de connaissance persistants dans le Gem (pas à joindre)
  • Interface simple et intuitive
❌ Faiblesses
  • Déclenchement manuel = sélection du Gem à chaque fois
  • Pas de génération native de .docx/.pptx (via Markdown + Google Docs)
  • Moins bon pour les tâches complexes d'exécution code

Choisir le bon outil

👉 Utilisez Claude si...

  • Vous avez besoin de générer des fichiers Office
  • Vous devez exécuter du code complexe (data processing, etc.)
  • Vous préférez déclenchement automatique

👉 Utilisez Gemini si...

  • Vous analysez de longs documents (2M tokens)
  • Vous travaillez dans l'écosystème Google
  • Vous avez besoin de persistance (fichiers de référence)

Ce que vous savez faire maintenant

  • Utiliser les skills Claude (DOCX, PPTX, PDF) et les Gems Gemini équivalents
  • Comprendre la différence entre déclenchement automatique (Claude) et manuel (Gemini)
  • Créer un SKILL.md avec YAML frontmatter, workflow, structure et règles critiques
  • Configurer un Gem Gemini avec instructions systèmes et fichiers de connaissance
  • Tester et itérer : identifier les problèmes et les corriger dans chaque plateforme
  • Choisir l'outil adapté selon le besoin : génération de fichiers → Claude, intégration Google → Gemini

Prochaines étapes

Avant votre prochain projet

  • Identifiez les tâches répétitives : ce sont vos futurs skills/gems
  • Écrivez vos configurations une fois, réutilisez-les 10 fois
  • Documentez vos workflows pour vos camarades de binôme
  • Partagez vos SKILL.md via Git, vos Gems via lien Gemini

Ressources recommandées

  • Documentation Claude : Visitez claude.ai/docs pour les best practices
  • Google AI Studio : aistudio.google.com pour explorer Gemini en détail
  • Communauté : Partagez vos skills/gems avec vos camarades et itérez ensemble

📋 Grille d'évaluation du TD

Critères

  • Clarté (20 pts) : Description et instructions sont-elles compréhensibles ?
  • Complétude (20 pts) : Couverture tous les cas d'usage du skill/gem ?
  • Qualité des résultats (20 pts) : Sortie structurée et professionnelle ?
  • Test & itération (20 pts) : Avez-vous testé et amélioré ?
  • Documentation (20 pts) : Pair review validé, exemples fournis

Bon courage pour vos projets futurs ! 🚀

Fichiers de connaissance : l'atout Gemini

Gemini Advanced permet d'attacher des fichiers de connaissance directement dans un Gem. Avantage clé : le fichier reste persistant dans le Gem, vous n'avez pas à le joindre à chaque session.

Comment faire

  • Allez dans la configuration du Gem, section « Connaissance »
  • Uploadez le fichier (Markdown, PDF, texte)
  • Gemini l'indexe automatiquement
  • Dans les instructions, dites : « Consulte le fichier codes-ac-but-mmi.md »

Exemple : Fichier de codes AC

Créez un fichier codes-ac-but-mmi.md avec les codes AC réels du BUT MMI. Voici la structure :

Contenu exemple :
# Codes AC - BUT MMI
## Semestre 3
- AC1101 : Web design
- AC1102 : Frontend development
- AC1201 : Marketing digital
...

Avantage sur Claude

Claude exécute des skills à partir de SKILL.md, mais les fichiers externes doivent être joints à chaque utilisation. Avec Gemini, c'est persistant et indexé.

Idées de Skills/Gems pour votre parcours MMI

Voici des outils que vous pourriez créer pour gagner du temps :

📋 Générateur de briefs

Brief de projet SAÉ, brief client, brief créatif. Format standard, sections obligatoires.

🎨 Fiche de persona

Générez des personas structurées pour vos projets UX : démographie, comportement, objectifs, frustrations.

📊 Rapport de test utilisateur

Analysez vos tests utilisateurs, générez un rapport structuré avec insights et recommandations.

🔧 Checker technique

Uploadez votre code, le skill/gem analyse la qualité, conformité, suggestions de refactoring.

À vous de jouer

  • Créez un fichier references/codes-ac-but-mmi.md avec au moins 5 codes réels
  • Importez-le dans votre Gem Gemini existant (configuration)
  • Testez : « Crée une fiche SAÉ avec uniquement des codes AC réels »

🤔 Questions de réflexion

  • Quel skill vous ferait gagner le plus de temps ce semestre ?
  • Préférez-vous déclenchement automatique (Claude) ou manuel (Gemini) ?
  • Comment partager vos skills/gems avec vos camarades de binôme ?

💡 Points clés à retenir

  • Une bonne config = gain de temps énorme
  • Mais elle nécessite de définir clairement le besoin en amont
  • Itération = clé du succès
  • Les deux plateformes sont complémentaires, pas antagonistes

Checklist avant de déployer

Pour votre SKILL.md (Claude)

  • ☑ Description liste ≥ 5 formulations déclencheuses
  • ☑ Description précise ce que le skill NE fait PAS
  • ☑ Workflow écrit à l'impératif et numéroté
  • ☑ Structure de sortie explicitement définie
  • ☑ Règles critiques dans une section dédiée
  • ☑ Testé avec 3 prompts différents
  • ☑ Fichier < 500 lignes (sinon : references/)

Pour votre Gem (Gemini)

  • ☑ Nom clair et mémorisable
  • ☑ Instructions structurées (numérotées ou tirets)
  • ☑ Format de sortie explicitement décrit
  • ☑ RÈGLES ABSOLUES en majuscules pour les contraintes
  • ☑ Fichiers de connaissance uploadés si nécessaire
  • ☑ Testé avec 3 prompts différents
  • ☑ Instructions < 2000 mots (au-delà : fichier joint)
